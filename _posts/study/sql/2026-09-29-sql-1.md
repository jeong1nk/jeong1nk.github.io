SQL을 공부하던 중 제일 자주 부딪히는 문제가 있었다.

바로

**"언제 서브쿼리를 사용해야 할까?"**

문법 자체는 어렵지 않은데  
막상 코딩테스트 문제를 풀다 보면 이게 서브쿼리를 써야 하는 문제인지 헷갈렸다.

그래서 문제를 풀면서 서브쿼리를 사용했던 경우와  
서브쿼리를 어느 위치에 사용하는지 정리해보았다.


## 📌 서브쿼리를 사용해야 할 때

### ① ~별 최대 / 최소 조건을 만족하는 전체 행을 가져와야 할 때

예를 들어

> 부서별 가장 높은 급여를 받는 직원의 정보를 가져와라.

```sql
SELECT *
FROM employee
WHERE (department, salary) IN (
    SELECT department, MAX(salary)
    FROM employee
    GROUP BY department
);
```

먼저 부서별 최대 급여를 구하고  -> 그 결과를 이용해서 실제 행을 가져온다.


### ② 집계 함수의 결과를 WHERE 조건에 사용해야 할 때

`MAX`, `MIN`, `AVG`, `COUNT` 등의 결과를  
다른 값과 비교해야 하는 경우이다.

예를 들어

> 전체 평균 급여보다 높은 직원 조회

```sql
SELECT *
FROM employee
WHERE salary > (
    SELECT AVG(salary)
    FROM employee
);
```

평균을 먼저 구한 뒤 -> 그 결과를 `WHERE` 조건에 사용한다.


### ③ 2단계 이상의 가공이 필요할 때

한 번 계산한 결과를 다시 가공해야 하는 경우이다.

예를 들어

> 부서별 평균 급여를 구한 뒤 평균 급여가 5000 이상인 부서 조회

```sql
SELECT *
FROM (
    SELECT department, AVG(salary) AS avg_salary
    FROM employee
    GROUP BY department
) result
WHERE avg_salary >= 5000;
```

1차로 데이터를 가공하고 -> 그 결과를 다시 조회한다.


이처럼 한 번의 쿼리로 끝내기 어렵고  
중간 결과가 필요한 경우 서브쿼리를 생각해볼 수 있다.


## 📌 서브쿼리의 위치

그러면 서브쿼리를 대체 어디에 넣어야 할까?

**"내가 필요한 계산 결과를 어느 단계에서 사용할까?"**

라고 생각하면서 정리해봤다.

### ① WHERE 절 서브쿼리

**"조건에 맞는 행을 뽑아내야 할 때"**

조건 필터링에 사용하며
주로 `IN`, `=`, `EXISTS` 등과 함께 사용한다.

```sql
SELECT *
FROM employee
WHERE salary > (
    SELECT AVG(salary)
    FROM employee
);
```

메인 테이블의 전체 컬럼은 그대로 유지하면서  
특정 조건에 맞는 행만 걸러내고 싶을 때 사용한다.


### ② FROM 절 서브쿼리

**"1차로 가공된 테이블을 만들어서 다시 사용해야 할 때"**

인라인 뷰 또는 가상 테이블이라고도 하며
서브쿼리에서 먼저 집계나 연산을 하고 그 결과를 하나의 테이블처럼 사용할 수 있다.

```sql
SELECT *
FROM (
    SELECT department, AVG(salary) AS avg_salary
    FROM employee
    GROUP BY department
) result
WHERE avg_salary >= 5000;
```

`ROW_NUMBER()`, `RANK()` 등으로 순위를 구한 뒤  
그 결과를 다시 조건으로 사용할 때도 자주 사용한다.


### ③ SELECT 절 서브쿼리

**"결과에 값 하나를 추가 컬럼으로 붙여야 할 때"**

스칼라 서브쿼리라고 하며
하나의 값(1행 1열)을 가져와 조회 결과에 추가할 수 있다.

```sql
SELECT
    employee,
    salary,
    (
        SELECT AVG(salary)
        FROM employee
    ) AS avg_salary
FROM employee;
```

각 행 옆에 전체 평균이나 전체 합계처럼  
하나의 값을 같이 보여주고 싶을 때 사용할 수 있다.


## 💡 정리

서브쿼리를 볼 때는

**"내가 필요한 값을 먼저 계산해야 하는가?"**

를 먼저 생각해보면 좋을 것 같다.

```text
WHERE
→ 조건에 맞는 행을 필터링

FROM
→ 1차 가공한 결과를 다시 사용

SELECT
→ 결과에 하나의 값을 추가
```

특히 코딩테스트에서

- ~별 최대 / 최소
- 평균보다 큰 / 작은 값
- 집계 결과와 비교
- 한 번 가공한 결과를 다시 가공

같은 조건이 나오면  
서브쿼리를 한 번 생각해보면 될 것 같다!
